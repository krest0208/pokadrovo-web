# Покадрово — отдельный запуск

Это существующее приложение 0.8: главная, монтажёр, регистрация, профили, серверное сохранение документов и админка. Интернет-хостинг не создан, Sites не опубликован. Компьютер, на котором запущена программа, временно выполняет роль сервера.

## Самый простой способ: готовый архив

1. Установите [Node.js 24 LTS](https://nodejs.org/) (допустим Node.js 22.16 или новее).
2. Полностью распакуйте ZIP в отдельную папку. Не запускайте файлы внутри окна ZIP.
3. **Windows:** откройте `start-standalone.bat`. **macOS/Linux:** откройте терминал в распакованной папке и выполните `bash start-standalone.sh`.
4. При первом запуске откроется браузерная форма: задайте логин владельца, пароль от 14 символов и повтор пароля. Можно нажать «Показать пароли». Если окно не открылось, скопируйте полную одноразовую ссылку из терминала. Ссылка действует 10 минут и работает только на вашем компьютере. Пароль не отправляется во внешние сервисы.
5. Откройте **http://localhost:5173**. Для входа владельца вручную введите **http://localhost:5173/krest0208!!!** в адресной строке. Ссылок на админку в меню, профиле и редакторе нет; `/admin` возвращает 404. Монтажёр — `/studio`, профиль — `/profile`.

Оставляйте окно запуска открытым. Для остановки нажмите Ctrl+C; повторный запуск использует прежнюю базу и не создаёт другого владельца. Если пароль потерян, восстановление выполняется отдельно по ADMIN-START.md; обычный запуск никогда не применяет `--reset`.

В готовом ZIP папка `dist` уже собрана. Для запуска не нужны npm, установка зависимостей или Docker; нужен только установленный Node.js. Если вы запускаете исходники без `dist`, скрипт установит зависимости из lockfile и соберёт приложение — для этого понадобится интернет.

## Где сохраняются данные

- `.pokadrovo-private` рядом с программой содержит SQLite, ключ и серверные настройки. Эта папка появится только при вашем первом запуске.
- Видео, музыка и фотографии остаются в браузере. Сервер хранит документы монтажа, а не облачные копии исходников.
- Используйте один адрес (`localhost`, не чередуйте с `127.0.0.1`) и тот же профиль браузера: хранилища разных адресов раздельны.
- Перед обновлением остановите программу и скопируйте всю `.pokadrovo-private` в закрытое резервное место. Чтобы обновиться, распакуйте программу в новую папку и перенесите туда **свою** приватную папку. Самостоятельно объединять SQLite и ключ от разных установок нельзя.
- Для хранения отдельно от программы можно задать `POKADROVO_DATA_DIR` — абсолютный путь вне `public` и `dist`. Пример macOS/Linux: `POKADROVO_DATA_DIR="$HOME/pokadrovo-data" bash start-standalone.sh`. На Windows используйте системную переменную или PowerShell: `$env:POKADROVO_DATA_DIR = 'C:\PokadrovoData'; .\start-standalone.bat`.

Если порт 5173 занят, сначала закройте вторую копию приложения. Дополнительно поддерживается `POKADROVO_PORT`; смена порта меняет origin и не переносит браузерные медиа автоматически. Адрес напечатает скрипт.

## Docker — дополнительный вариант

Для компьютера с Docker Engine/Desktop и Compose. Конфигурация уже подготовлена, но Docker-движок в среде подготовки отсутствует: сборка образа и работа Docker volume здесь не проверены.

В папке проекта выполните последовательно:

```sh
docker compose build
docker compose run --rm app node server/setup.mjs
docker compose up -d
docker compose ps
```

Вторую команду выполняйте в интерактивном терминале только при первой установке. Если владелец уже существует, пропустите её. Затем откройте http://localhost:5173.

Логи: `docker compose logs --tail=50 app`. Остановка: `docker compose stop`. Повторный запуск: `docker compose up -d`. Эти команды сохраняют данные. `docker compose down -v` удаляет том с данными — для обычной остановки эту команду не используйте.

SQLite и ключ находятся в именованном Docker volume `private-data`, смонтированном в `/data`. Он отделён от образа и сохраняется при пересборке. Это отдельная установка: она автоматически не импортирует базу локального запуска. В архиве нет ни готового тома, ни базы, ни ключа.

Порт Docker привязан только к `127.0.0.1` хоста. Контейнер работает от непривилегированного пользователя с read-only корневой файловой системой; запись разрешена в том данных и временный каталог. Внутренний входной порт контейнера не означает публикацию в интернете. У Docker предусмотрен healthcheck `/api/health`.

## Дальнейшее подключение к Sites

Локальный адрес недоступен ChatGPT Sites. Для подключения потребуется отдельная машина/хостинг с HTTPS-адресом и постоянным диском, затем защищённый серверный шлюз Sites. Домен и платный сервер этим комплектом не подключаются, аккаунт хостинга не создаётся.

В Docker можно заранее задать `POKADROVO_PUBLIC_ORIGIN` с будущим HTTPS-origin через окружение Compose. Само это значение не создаёт TLS: HTTPS должен обслуживаться настроенным reverse proxy. В текущей поставке открытие внешних портов и настройка прокси намеренно не выполняются.

Нужно сохранить проверки Host/Origin, CSRF, cookie, административной роли и корректные OAuth callback. Изменение разрешённых iframe-origin для ChatGPT и соединение шлюз → backend — следующий этап; готовность этого соединения сейчас не заявляется.

## Что сохранено

Исходный интерфейс, редактор и серверные обработчики не переписаны. Настоящая нейросеть, почтовое подтверждение/восстановление и платежи по-прежнему не подключены. Социальный вход требует ваших OAuth-приложений; MP4 зависит от браузера. Подготовка запуска не меняет эти ограничения.

Проверка запуска: `node --test tests/standalone.test.mjs` после сборки. Она использует отдельные временные базы и случайные тестовые пароли, проверяет вход/сохранение/перезапуск и не затрагивает вашу рабочую базу.

Основа Docker-конфигурации: [официальный Node image](https://github.com/nodejs/docker-node), [Compose services](https://docs.docker.com/reference/compose-file/services/), [volumes](https://docs.docker.com/engine/storage/volumes/).
