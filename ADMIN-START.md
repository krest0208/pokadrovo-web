# Покадрово 0.7 — панель единственного владельца

Панель не публикуется на хостинг. Она запускается вместе с локальным сервером проекта. Самостоятельный HTML-файл не может безопасно хранить пароль администратора и API-ключ, поэтому для этой функции добавлен сервер.

## Первый запуск

Нужен Node.js **22.16 или новее** (поддерживаемая LTS-версия).

```sh
npm install
npm run admin:setup
npm run build
npm start
```

Сайт: `http://localhost:5173`. Панель: `http://localhost:5173/admin`.

Команда настройки предложит логин (по умолчанию `krest0208`) и дважды попросит пароль. Используйте уникальную парольную фразу длиной не менее 14 символов. Пароль не отображается, не передаётся по сети, не попадает в исходники. **Общего пароля по умолчанию нет. Не присылайте пароль или API-ключ в чат.**

Для разработки: `npm run dev` запускает Vite на 5173 и API на 5174 с проксированием `/admin`, `/owner-assets`, `/api`. Команда `npm run dev:web` запускает только Vite, без админ-сервера. При работе с production-сборкой (`npm start`) счётчик запросов главной учитывает реальные HTTP-открытия. В режиме Vite он не учитывает главную: её отдаёт сам Vite; события с согласием работают в обоих режимах.

## Что доступно

- Обзор за 7 / 30 / 90 дней: запросы главной, приблизительные уникальные браузеры с согласием, открытия редактора, уникальные сохранённые проекты и все сохранения, сформированные видео, распределение по форматам/устройствам.
- График и доступная текстовая таблица, обновление по кнопке. Часовой пояс отчётов: UTC.
- ИИ/API: провайдер, идентификатор модели, запись/замена/удаление ключа, переключатель аналитики. Секрет не возвращается браузеру. Сохранение не проверяет ключ у провайдера и не запускает ИИ.
- Смена пароля, необязательный второй фактор TOTP, журнал входов и важных действий.

Регистрация обычных пользователей, покупки, выручка, фактическая стоимость ИИ и провайдерский адаптер пока не подключены. В панели они так и отмечены, а не отображаются как выдуманные данные. История старого домена не переносится автоматически.

## Доступ и безопасность

В базе допускается ровно один владелец, публичного создания администраторов нет. Каждый успешный вход завершает прежний сеанс. Сеанс ограничен 12 часами и 30 минутами простоя. Сервер проверяет авторизацию на каждом приватном маршруте. Используются HttpOnly / SameSite=Strict cookies, CSRF-токен и проверка Origin/Host, ограничение попыток входа. На HTTPS включаются Secure и префикс __Host-. Авторизационных токенов в localStorage нет.

Пароль хешируется scrypt (`N=131072, r=8, p=1`, индивидуальная соль). API-ключ и секрет второго фактора зашифрованы AES-256-GCM. Ключ шифрования хранится отдельно от базы. Это защита хранения, а не гарантия от компрометации всего сервера: доступ к серверной учётной записи также нужно защищать.

**После первого входа рекомендуется включить «Защита доступа → Код с телефона».** Секрет добавляется вручную в приложение-аутентификатор; никаких внешних QR-сервисов нет. При утрате доступа запустите на своём сервере `npm run admin:setup -- --reset`. Сброс меняет пароль, отключает второй фактор и отзывает сеансы. Публичного сброса через сайт нет.

## Личные файлы сервера

Вся закрытая информация находится в `.pokadrovo-private/` (или в каталоге `POKADROVO_DATA_DIR`): `owner.sqlite`, WAL-файлы SQLite и `master.key`. Каталог исключён из Git и закрыт для статического сервера/Vite. На POSIX создаётся с правами 0700, файлы — 0600; на Windows нужно защищать каталог правами своей учётной записи.

Не добавляйте эти файлы, `.env`, пароли и ключи в GitHub, архив исходников или чат. Для резервной копии остановите сервер и скопируйте **всю** закрытую папку в надёжное место. Если `master.key` потерян, восстановите его из приватной резервной копии. Приложение не создаёт молча новый ключ поверх существующей базы.

## Как считается статистика

«Запросы главной» — HTTP GET `/`, включая перезагрузки и ботов, без IP-адреса в отчёте. «Уникальные браузеры» — приблизительные отдельные браузеры только среди пользователей, разрешивших события. Это не точное количество людей.

Редактор запрашивает добровольное согласие на события. DNT/GPC запрещают их отправку. Через кнопку «Приватность» можно отказаться; ранее записанные события этого браузера удаляются. Не передаются медиа, имена файлов, промпты, пароли, почта или API-ключи. Случайные идентификаторы проекта и браузера хешируются сервером.

Счётчик проектов растёт после фактического успешного сохранения в localStorage. Экспорт учитывается при отправке готового video-Blob на скачивание, но не подтверждает, что пользователь сохранил файл. Клиентские события могут блокироваться/подделываться и **не подходят для расчёта оплаты**. Финансовые события нельзя записать через публичный collector.

Сырые события хранятся 90 дней, агрегаты главной — 365 дней, журнал доступа — 180 дней. Сессии и ограничения входа очищаются автоматически.

## Когда будем публиковать на домене

По умолчанию сервер слушает только `127.0.0.1`. Автодеплоя нет. Для будущего домена настройте TLS на reverse proxy, передайте исходный Host и задайте `POKADROVO_PUBLIC_ORIGIN=https://your-domain.example`. API лучше оставить на loopback за прокси. Публичный HTTP-origin не допускается. Заголовки X-Forwarded-For намеренно не считаются доверенными: за прокси лимит будет общий, пока не реализована проверенная настройка доверенных прокси.

Перед публикацией нужны отдельный security review, резервирование базы, TLS/домен, контроль инфраструктуры и проверка применимых требований к аналитике. Наличие пароля не позволяет обещать абсолютную неуязвимость.

Тесты: `npm run test:admin`. Сведения о проверках: `docs/ADMIN-QA.md`.
