# Кабинет владельца — Покадрово 0.8

Полная инструкция по регистрации, социальному входу и запуску: [ACCOUNTS-START.md](ACCOUNTS-START.md).

## Локальный запуск

Node.js 22.16+. Самый простой запуск: `start-standalone.bat` на Windows или `bash start-standalone.sh` на macOS/Linux. При первой установке откроется форма создания владельца в браузере. Готовый архив с `dist` не требует установки зависимостей; исходники из GitHub скрипт соберёт автоматически. Подробности: [STANDALONE-START.md](STANDALONE-START.md).

Сайт: `http://localhost:5173`. Кабинет: `http://localhost:5173/krest0208!!!`. Введите этот адрес вручную; старый `/admin` возвращает 404. Скрытый адрес не заменяет пароль и серверную проверку доступа. Профиль: `/profile`. Студия: `/studio`.

В публичном коде нет готового пароля или базы. При запуске через `start-standalone` единственный владелец создаётся в локальной форме браузера по одноразовой ссылке. Альтернатива для терминала — `npm run admin:setup`. Персональные данные доступа из отдельной приватной поставки действуют только в её локальной базе, не в GitHub и не на прежнем хостинге.

## Что доступно

Статистика запросов главной, события редактора с согласием, график и таблица за 7/30/90 дней. Настоящие регистрации из SQLite, список пользователей с поиском, количество проектов. Настройки ИИ API-ключа и отдельные настройки Google/Facebook/Instagram OAuth. ИИ и платежи пока не подключены; ключ сам по себе не запускает обработку.

В разделе «Защита доступа» можно менять логин и/или пароль владельца. Нужен текущий пароль; все старые сеансы завершаются. Для смены только логина оставьте новый пароль пустым. Включите дополнительный код с телефона (TOTP). При потере доступа только локально: `npm run admin:setup -- --reset`; это меняет владельца и его защиту, но не удаляет обычных пользователей и проекты.

## Защита

Сервер проверяет каждый закрытый API-запрос. Публичная регистрация не выдаёт административных прав. Один владелец и один активный сеанс: новый вход завершает старый. Простой — не более 30 минут, общий срок — 12 часов. HttpOnly/SameSite cookie, проверка Origin/Host, CSRF, ограничения попыток. На HTTPS включены Secure и __Host-.

Пароль — scrypt с индивидуальной солью. API-ключи, OAuth-секреты и TOTP зашифрованы AES-256-GCM. Ключ шифрования находится отдельно от SQLite в `.pokadrovo-private/master.key`. Это не защита от захвата всей серверной учётной записи. Папку `.pokadrovo-private`, базу, ключ и приватную инструкцию никогда не публикуйте. Для резервной копии остановите сервер и сохраните всю закрытую папку; не заменяйте существующую базу тестовой.

## Показатели и ограничения

Запросы страницы включают обновления и ботов. Уникальные браузеры приблизительные, учитываются только после согласия; это не число людей. Клиентские события не подходят для биллинга. DNT/GPC отключают события. Регистрации считаются отдельно по базе аккаунтов. Исходные медиа не отправляются на сервер; профиль и параметры монтажа, включая бриф, сохраняются в аккаунте.

События хранятся 90 дней, агрегаты главной — 365, журнал действий — 180. В Vite главную отдаёт dev-сервер, поэтому её HTTP-запросы не попадают в серверный счётчик; используйте `npm start` для этого показателя.

## Перед публикацией

Автодеплоя нет. Сервер по умолчанию слушает `127.0.0.1`. Публичный origin должен быть HTTPS. Задайте `POKADROVO_PUBLIC_ORIGIN`, настройте TLS и передачу Host, защитите приватную папку, проверьте реальные входы Google/Meta и резервное копирование. Произвольный X-Forwarded-For не считается доверенным: за прокси лимиты общие до отдельной настройки доверенных адресов. Разработческий сервер Vite не предназначен для публичного сайта.

Проверки: `npm run test:admin`. Границы проверок: [docs/ACCOUNTS-0.8-QA.md](docs/ACCOUNTS-0.8-QA.md).
