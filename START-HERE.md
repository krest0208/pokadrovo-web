# Покадрово — единый сайт

В комплекте одна серверная сборка: существующая главная с анимациями, монтажёр, проекты без регистрации и защищённая административная панель. Её можно запускать локально или на выделенном VPS; состояние размещения описано в [DOMAIN-DEPLOY.md](DOMAIN-DEPLOY.md).

## Открыть на своём компьютере

1. Установите Node.js 24 (допустимо 22.16 или новее).
2. Полностью распакуйте архив в отдельную папку.
3. Windows: откройте `start-standalone.bat`. macOS/Linux: выполните `bash start-standalone.sh` из этой папки.
4. При первом запуске создайте владельца в открывшейся локальной форме. Готового пароля в комплекте нет.
5. Откройте `http://localhost:5173`. Терминал должен оставаться открытым.

| Адрес | Что открывается |
| --- | --- |
| `/` | Главная страница |
| `/studio` | Монтажёр обычного видео и Reels, без регистрации |
| `/projects` | Проекты этого браузера, импорт и экспорт JSON |
| `/krest0208!!!` | Вход владельца и настоящая админ-панель |

Адрес владельца вводится вручную в адресной строке. Его нет в публичном меню. Сама необычная ссылка не заменяет пароль: все административные API проверяют сеанс владельца.

## Начальный пароль владельца и его смена

При первой настройке из исходников можно выполнить `npm run admin:setup -- --generate` в своём приватном интерактивном терминале. Команда создаст владельца `krest0208` со случайным паролем из 43 символов и покажет его один раз после успешного создания. В базе сохраняется только scrypt-хэш; пароль не записывается в исходники или отдельный файл. Сохраните его в менеджере паролей, не перенаправляйте вывод в журнал и не публикуйте снимок терминала.

После входа нажмите **«Сменить пароль»** в верхней части админки или откройте **«Защита доступа»**. Укажите текущий пароль, собственную новую фразу от 14 символов и её повтор. После сохранения прежний пароль и все старые сеансы перестают работать. Новый пароль вводите самостоятельно: его не нужно передавать в чат.

`--generate` работает только при первом создании: существующего владельца, пароль или второй фактор он не заменяет. Для восстановления остаётся интерактивная команда `npm run admin:setup -- --reset`. При обновлении сервера не запускайте первую настройку повторно.

## Что работает и где данные

Сохранены таймлайн, импорт видео/фото/музыки, обрезка, скорость, звук, трансформации, текст, отмена действий и исходный диалог экспорта. MP4 зависит от браузерного кодировщика; WebM остаётся основным вариантом. Проверка длительного экспорта реальных видео на вашем устройстве ещё нужна.

Без регистрации документы монтажа и исходники хранятся в браузере этого адреса. Страница «Мои проекты» позволяет скачать JSON с монтажом; он не содержит исходные медиафайлы. При смене компьютера, браузера или домена сохраните JSON и исходники отдельно. Это не облачная синхронизация медиа. Проекты из прежнего окна в чате переносятся через «Скачать проекты JSON» → «Открыть проект JSON» на сайте; исходники добавляются отдельно.

Владелец после входа сохраняет свои документы проектов через прежний защищённый серверный механизм. Существующие пользовательские базы не удаляются. Регистрация и вход посетителей по умолчанию отключены и в интерфейсе, и на сервере. Для возврата прежнего режима существует настройка `POKADROVO_ACCOUNTS_ENABLED=1`.

Админ-панель → «Подключение нейросети»: провайдер, модель, API-ключ, удаление ключа. Ключ сохраняется зашифрованным с подтверждением пароля владельца. Реальные запросы к модели и автоматический ИИ-монтаж **ещё не реализованы**. Сохранение ключа не означает подключение нейросети.

SQLite и ключ шифрования создаются при первом запуске в `.pokadrovo-private`. В архиве их нет. Перед обновлением остановите сайт и сохраните всю эту папку отдельно. Не выкладывайте её в GitHub и не кладите в `dist` или `public`.

## Позднее разместить на домене

Порядок действий и подготовленная конфигурация — в [DOMAIN-DEPLOY.md](DOMAIN-DEPLOY.md). Домен без сервера не исполняет Node.js и SQLite. Для этой поставки нужен сервер/VPS с постоянным диском; обычная загрузка одного HTML на статический хостинг недостаточна.

Для работы из исходников: `npm ci`, `npm run build`, `npm run admin:setup` (только первая настройка), `npm start`. В этом архиве `dist` уже собран, поэтому отдельный запуск не требует npm или Docker.
