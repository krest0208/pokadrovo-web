# Покадрово 0.8 — регистрация, профиль и владелец

> Обновление 19 октября 2026: сайт работает на https://pokadrovo.ru/. Доступна регистрация только по почте и паролю с дополнительным гостевым монтажом. Актуальные настройки и обновление VPS: [docs/EMAIL-ACCOUNTS.md](docs/EMAIL-ACCOUNTS.md). Описания OAuth ниже относятся к сохранённому коду для будущего использования; сейчас эти маршруты и настройки отключены.

## Локальный запуск

Нужен Node.js 22.16 или новее. Откройте `start-standalone.bat` (Windows) или выполните `bash start-standalone.sh` (macOS/Linux). При первом запуске пароль владельца задаётся в браузере. Готовая сборка с `dist` не требует установки зависимостей; исходники из GitHub скрипт соберёт автоматически.

При запуске из GitHub: `npm install`, `npm run build`, затем `npm start`. Для разработки: `npm run dev` запускает Vite и тот же сервер API. Адрес сайта — `http://localhost:5173`, профиля — `/profile`, студии — `/studio`, админки — `/krest0208!!!`.

Ссылка localhost работает только на компьютере, где запущен сервер. Отдельный HTML больше не может заменить настоящий вход и админ-панель. Никакого размещения сайта или автодеплоя в этом обновлении нет.

## Как создаётся владелец

В публичном репозитории **нет готового пароля, аккаунта или базы**. При чистой установке запустите `start-standalone.bat` или `bash start-standalone.sh`: откроется локальная форма создания владельца с кнопкой показа пароля. Альтернатива для терминала: `npm run admin:setup`. В персональной приватной сборке, переданной владельцу отдельно, аккаунт уже создан; его данные находятся в отдельной приватной инструкции, не в GitHub.

Войти владельцем можно только через отдельную страницу `/krest0208!!!`: введите полный адрес в адресной строке браузера. Ссылок на этот вход в интерфейсе сайта нет. После входа доступны профиль, монтажная и админ-панель. Сменить логин и/или пароль: **Админ-панель → Защита доступа**. Изменения требуют текущего пароля и завершают старые сеансы. Для изменения только логина оставьте поля нового пароля пустыми. Рекомендуется включить TOTP (код с телефона).

Не публикуйте `.pokadrovo-private`, `master.key`, SQLite, резервные копии или приватную инструкцию с паролем. Для резервной копии сначала остановите сервер и сохраните всю `.pokadrovo-private`. Не заменяйте существующую рабочую базу чужой или тестовой копией. При утере доступа локальный `npm run admin:setup -- --reset` заменяет учётную запись владельца, но не удаляет проекты и обычных пользователей.

## Регистрация пользователей

Email + пароль работают без сторонних сервисов. Минимум — 14 символов; данные доступа хешируются scrypt. У каждого пользователя свой профиль, свои серверные документы проектов и своё локальное пространство медиа. Нельзя получить права владельца через регистрацию, имя, почту, роль в JSON или localStorage.

Email в этой версии **не подтверждается письмом**. Доставка писем, восстановление по email и безопасное объединение социальных аккаунтов пока не подключены. Не используйте неподтверждённую почту как доказательство личности или для назначения прав. Смена имени и пароля доступна в профиле. После смены пароля требуется войти снова.

Все переходы к созданию/открытию проекта проходят проверку сеанса; если гость нажал кнопку под блоком соцсетей, после входа создаётся проект выбранного формата. Главная открыта без регистрации. Публичный JavaScript не является защитой от изменения клиентского кода; серверные данные и административные действия защищены независимо.

## Настройка Google, Facebook, Instagram

В админ-панели появился раздел **«Вход и регистрация»**. Для каждого провайдера задаются Client ID, Client Secret, включение и (для Meta) поддерживаемая вашим приложением версия Graph API. Callback формируется сервером из `POKADROVO_PUBLIC_ORIGIN` и показан в панели; пользователь не может подменить его произвольным адресом. Секреты зашифрованы, при чтении панели не возвращаются.

### Google

Создайте OAuth-приложение типа Web application, настройте экран согласия и тестовых пользователей. Впишите точный redirect URI, например `http://localhost:5173/auth/google/callback` для разработки. Используются только `openid email profile`, authorization-code flow, PKCE S256, state и nonce; подпись ID token проверяется на сервере, идентификатор сверяется с userinfo.

Документация: https://developers.google.com/identity/protocols/oauth2/web-server и https://developers.google.com/identity/openid-connect/openid-connect

### Facebook

Создайте приложение Meta с Facebook Login, укажите поддерживаемую Graph API version и точный HTTPS callback `/auth/facebook/callback`. На локальном HTTP кнопка намеренно отключена. Необходимо выполнить условия Meta для режима разработки/публичного доступа и разрешённых пользователей; в зависимости от конфигурации могут требоваться проверки приложения. Сервер проверяет принадлежность токена приложению и совпадение user ID, запрашивает только `public_profile,email`.

### Instagram — важное ограничение

Официальный Instagram Login предназначен для **профессиональных аккаунтов Business/Creator**, не для произвольного личного аккаунта. Это НЕ универсальная замена «Войти через Instagram» для всех посетителей. Используется минимальное разрешение `instagram_business_basic`; публикация видео от имени пользователя не запрашивается. Настройте Instagram-приложение, Client ID/Secret, версию API и точный HTTPS callback `/auth/instagram/callback`.

Официальная коллекция Meta: https://www.postman.com/meta/workspace/instagram/documentation/23987686-9386f468-7714-490f-9bfc-9442db5c8f00

**Вход с реальными аккаунтами соцсетей в этой поставке не проверен:** ключей и настроенных приложений владельца не было. Пока они не заданы, кнопки видны, но отключены с объяснением. Не присылайте Client Secret в чат. Равная почта в Google и локальном аккаунте не объединяет их автоматически — это намеренная защита от захвата аккаунта.

## Проекты и файлы

Сервер сохраняет документы монтажа (порядок клипов, настройки, тексты, бриф), но не исходные видео/фото/музыку. На другом компьютере этих исходников может не быть: облачной синхронизации медиа пока нет. Каждый исходник отделён по аккаунту в IndexedDB. Старые проекты версии 0.7 можно явно перенести в аккаунт **владельца** кнопкой в его профиле. Этот перенос доступен только в том браузере и на том origin, где они были сохранены; он не объединяет хранилища различных доменов.

Метаданные также остаются локально для восстановления при сбое API. Общие компьютеры и локальный доступ к профилю браузера не считаются изолированной средой: выход не шифрует локальные файлы. Для конфиденциальных материалов используйте отдельный профиль ОС/браузера.

## Админка и показатели

Настоящие регистрации, таблица пользователей, поиск, количество их проектов и выбор OAuth доступны только владельцу. Графики посещений остаются из прежней админки; клиентская аналитика включается с согласия и не является биллингом. Платежи и ИИ-провайдер не подключены. Новый секрет OAuth не является API-ключом нейросети: это разные настройки.

## Перед доменом

Нужно HTTPS, `POKADROVO_PUBLIC_ORIGIN=https://ваш-домен`, корректная конфигурация прокси/Host, резервные копии, реальные настройки провайдеров, проверка входа/выхода на браузерах и телефонах, политика данных, почтовый сервис при необходимости. Сервер по умолчанию слушает только loopback. Не выставляйте приватную папку как статический каталог. Клиентская разработческая версия Vite не предназначена для публичного размещения.
