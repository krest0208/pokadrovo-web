# Автоматическая публикация Покадрово

Разрешение владельца на обычные коммиты и публикацию без повторного подтверждения записано в `AGENTS.md`. После выполнения задачи ассистент проверяет изменения и сохраняет только относящиеся к ней файлы в `krest0208/pokadrovo-web`, ветку `main`.

Серверный агент работает отдельно от чата. Он не придумывает изменения и не отправляет произвольные файлы с сервера в GitHub. Его задача — автоматически установить готовый, проверенный коммит.

## Как проходит обновление

1. Таймер VPS проверяет текущую `main` примерно раз в три минуты.
2. Учитывается только успешный push-запуск `Check Pokadrovo Web` для этого SHA, в этом репозитории и этой ветке. Проверки pull request, форка или другой ветки не подходят.
3. Архив ровно этого коммита загружается с GitHub. Пути, ссылки, приватные файлы и размеры проверяются перед распаковкой.
4. Отдельный системный пользователь `pokadrovo-build` устанавливает зависимости без lifecycle-скриптов, выполняет серверные тесты, TypeScript, Vite, проверки редактора и автономного запуска. Сборка ограничена отдельной systemd-службой; рабочая база, ключи и резервные копии ей недоступны.
5. Перед установкой агент повторно проверяет `main`. Устаревшая сборка уступает место новому коммиту.
6. Сайт ненадолго останавливается. Агент сохраняет согласованную приватную резервную копию, переключает каталог приложения и запускает прежнюю службу `pokadrovo.service` с прежними настройками.
7. Проверяются локальное API, выдача нового HTML, защита проектов и HTTPS на `pokadrovo.ru`. Только после этого SHA записывается как установленный.
8. При ошибке возвращается предыдущий код. База аккаунтов автоматически не откатывается. Журнал позволяет восстановить прерванное переключение при следующем запуске.

GitHub-токен, SSH-ключ, пароль root и открытый порт для входящих команд агенту не нужны: он читает публичный репозиторий сам. Его управляющие файлы установлены отдельно от приложения, принадлежат root и не заменяются кодом из `main` при обычном обновлении. Обновление самого управляющего агента требует отдельной переустановки.

## Однократное включение

Нужно один раз запустить `deploy/bootstrap-autodeploy-vdsina.sh` с полным SHA выбранного установочного коммита в root-консоли уже работающего VPS. Скрипт рассчитан только на **138.16.185.3**, **pokadrovo.ru**, `/opt/pokadrovo/app` и `/var/lib/pokadrovo`. Он проверяет существующую службу и включает `pokadrovo-autodeploy.timer`.

Файлы:

- `deploy/bootstrap-autodeploy-vdsina.sh` — загрузка выбранной установочной версии.
- `deploy/autodeploy/install-vdsina.sh` — установка фиксированного агента и systemd-таймера.
- `deploy/autodeploy/agent.mjs`, `core.mjs` — получение версии, сборка, переключение и восстановление.
- `deploy/autodeploy/worker.mjs` — проверки под отдельным пользователем.
- `deploy/autodeploy/unpack.py` — ограниченная распаковка исходников.

Установка не создаёт владельца сайта, не меняет его пароль, DNS, Caddy, тарифы или API-ключи. Она не включает платные запросы ИИ.

## Проверка работы

```bash
systemctl status pokadrovo-autodeploy.timer
journalctl -u pokadrovo-autodeploy.service -n 30 --no-pager
```

После успешной публикации текущий SHA доступен в `/pokadrovo-release.json` и метатеге `pokadrovo-release` главной страницы. Пока этих признаков нет, нельзя считать сайт обновлённым только по успешному коммиту или включённому таймеру.

### Ошибка `uv_interface_addresses`, код 97

В ранней версии управляющей службы список `RestrictAddressFamilies` не включал `AF_NETLINK`. В Linux перечисление сетевых интерфейсов для проверки IP VPS использует netlink; служба останавливалась до загрузки исходников. Исправленная конфигурация разрешает `AF_NETLINK`, сохраняя остальные ограничения и проверку привязки к VPS. Регрессионный тест воспроизводит отказ настоящего `os.networkInterfaces()` под seccomp, затем проверяет вызов с разрешёнными семействами из файла службы (Linux с libseccomp).

Для уже установленного агента нужно однократно повторить bootstrap с полным SHA исправленного коммита: обычное обновление сайта не заменяет управляющую службу. Установщик перезагрузит конфигурацию systemd и запустит проверку. Эта ошибка не означает повреждение данных сайта.

### Сборка останавливается во время успешных тестов

У раннего сборщика каждый этап имел лимит 240 секунд. На VPS с одним CPU последовательные серверные тесты не успевали закончиться: журнал показывал успешные проверки, затем общий отказ без причины. Для серверных тестов и проверок аккаунтов лимит увеличен до 600 секунд; остальные этапы сохраняют 240 секунд, а вся изолированная сборка по-прежнему ограничена systemd в 900 секунд. Тесты выполняются в один поток, ограничения памяти и доступа к рабочим данным сохраняются.

Сборщик пишет название, лимит и длительность каждого этапа. При остановке он различает превышение времени, код выхода, сигнал и ошибку запуска. Подробный вывод доступен в журнале отдельной службы `pokadrovo-build-<первые 12 символов SHA>-<PID>.service`; её имя выводится в журнале `pokadrovo-autodeploy.service`. Для применения нового лимита к уже установленному управляющему агенту также требуется повторный bootstrap с SHA исправления.

Остановить будущие автоматические обновления, дав текущему закончиться:

```bash
systemctl disable --now pokadrovo-autodeploy.timer
```

Разовый запуск проверки:

```bash
systemctl start pokadrovo-autodeploy.service
```

Повторная ошибка того же SHA повторяется не чаще раза в 15 минут; новый коммит проверяется без этой задержки. Сохраняются три предыдущих рабочих каталога и три неудачные попытки с приватными резервными копиями. Другие резервные копии агент не удаляет. Старые хешированные ресурсы на время сохраняются для открытых вкладок.

## Границы установки и проверок

Код агента и его тесты в GitHub — ещё не работающий таймер на VPS. В этой сессии автоматический доступ к серверной консоли ранее был отклонён проверкой безопасности. Активация остаётся однократным ручным действием; обход ограничения не предусмотрен.

Проверки в репозитории моделируют файловое переключение и настоящий откат в изолированных каталогах, проверяют привязку CI к коммиту, запрет ссылок и приватных файлов, права публичных ресурсов и восстановление журнала. Запуск systemd-служб на реальном VPS подтверждается отдельно после установки.

Технические источники: [GitHub workflow runs API](https://docs.github.com/en/rest/actions/workflow-runs), [systemd-run](https://www.freedesktop.org/software/systemd/man/latest/systemd-run.html), [systemd execution isolation](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html).
