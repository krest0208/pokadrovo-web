# Регистрация по почте и паролю · 19 октября 2026

Production на `https://pokadrovo.ru/` использует:

```ini
POKADROVO_ACCOUNTS_ENABLED=1
POKADROVO_GUEST_EDITING=1
POKADROVO_SOCIAL_LOGIN_ENABLED=0
```

Пользователь указывает почту, пароль от 14 символов и повтор пароля, знакомится с условиями хранения данных. Имя не требуется; его можно изменить в профиле. Регистрация сразу создаёт обычный пользовательский сеанс, без прав владельца. Доступны вход, выход и смена пароля с подтверждением текущего. Смена пароля завершает все сеансы пользователя.

Отправка писем, проверка владения почтой и восстановление пароля письмом не подключены. Интерфейс сообщает об этом; почта остаётся неподтверждённой. Не использовать её как проверенную личность или разрешение на объединение аккаунтов.

Гость продолжает работу со своей прежней библиотекой `guest-local`. Регистрация не переносит и не удаляет её. После входа открывается отдельная библиотека аккаунта. На сервер уходят только параметры монтажа; исходные медиа остаются на устройстве. При выходе из аккаунта гостевые проекты снова доступны в этом браузере. Приватные API требуют сеанс и проверяют принадлежность проекта.

Социальных кнопок в форме нет. При `POKADROVO_SOCIAL_LOGIN_ENABLED=0` сервер отклоняет начало OAuth, callbacks и изменение настроек провайдеров даже при сохранённых ранее ключах. Раздел OAuth в админке скрыт. Настройки владельца, его пароль и ключ шифрования не меняются при обновлении.

## Обновление существующего VPS

Из отдельной копии **проверенного фиксированного коммита** запустить от root:

```sh
bash deploy/enable-email-accounts-vdsina.sh
```

Скрипт разрешён только на выделенном VPS 138.16.185.3 с рабочей установкой `/opt/pokadrovo/app` и приватной папкой `/var/lib/pokadrovo`. Он сначала собирает и проверяет исходники, затем сохраняет код и согласованную копию приватной папки в `/opt/pokadrovo/backups` с доступом только root. Служба ненадолго останавливается. База и ключ остаются на месте. DNS, Caddy и пароли не меняются.

В systemd создаётся только drop-in `pokadrovo.service.d/email-accounts.conf`. Старые хешированные ресурсы сохраняются для открытых вкладок. При ошибке восстанавливаются код и этот drop-in; приватная база автоматически не откатывается, чтобы не потерять новые регистрации.

Проверки: реальные HTTP-тесты регистрации/входа/выхода, паролей, CSRF, cookie, разграничения проектов и запрета OAuth; тест сохранения гостевой библиотеки; TypeScript и Vite. Продакшен-проверка не создаёт тестовых аккаунтов и не читает персональные данные.
