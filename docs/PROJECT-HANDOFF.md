Сверка выполнена 17 октября 2026 года. Основная версия приложения — 0.8.

## Главное решение

Покадрово — будущий **ИИ-видеомонтажёр со своим редактором**, а не просто редактор с дополнительной кнопкой ИИ. Пользователь формулирует замысел; в дальнейшем агент должен предлагать проверяемый план и выполнять операции в том же проекте, который доступен для ручных правок и отмены.

Сейчас развивается веб-версия в `krest0208/pokadrovo-web`, ветка `main`. Нативный Android остаётся отдельно в `krest0208/pokadrovo`. Не заменять Android на WebView и не переносить функции туда без отдельного решения владельца.

**Публикация запрещена без нового указания владельца.** Текущая работа сохраняется в GitHub и запускается локально. Прежний адрес на Higgsfield не является подтверждением актуального состояния приложения. GitHub не заменяет сервер регистрации и админки.

## Что сохранено в основной версии

Главная содержит многослойную композицию, светлую и тёмную темы, анимации по видимости блока, ввод замысла и выбор формата для площадки. У гостя в шапке — регистрация; после входа доступен профиль. Переход с нижнего блока площадок сохраняет выбранный формат при создании проекта.

Монтажёр поддерживает обычное и вертикальное видео, импорт видео/фото/аудио, обрезку, разделение, удаление диапазонов, скорость, звук и музыку, контекстные меню, трансформации изображений, маски, текст, выбор гарнитур, импорт SRT, отмену и повтор. Панели можно выводить на передний план. Экспорт WebM включает звук; MP4 зависит от доступного браузерного кодировщика.

ИИ-панель сохраняет задание и проверяет/симулирует план перед применением. Подготовлены два независимых режима: Qwen Omni для Reels 9:16 до 60 секунд (бесплатная проба: один проект, три запроса, семь дней) и Яндекс AI Studio для будущего платного монтажа. Яндекс сейчас получает только текст/структуру проекта и предыдущий анализ; видео/звук разбирает Qwen по отдельному согласию. Администратор тестирует оба без внутренних списаний; расходы API остаются у владельца. Яндекс закрыт обычным аккаунтам до разработки тарифа/платежей. Ключи раздельные, публичная проба по умолчанию закрыта. Изменение кода не подтверждает установку на VPS или реальный ответ моделей. Подробности: [AI-ACCESS-AND-YANDEX.md](AI-ACCESS-AND-YANDEX.md).

Регистрация по почте и паролю, профиль, документы проектов по аккаунтам и отдельный доступ владельца реализованы на сервере. Админка содержит аналитику, пользователей, настройки социального входа, поля API-провайдера и защиту доступа. Серверные проверки доступа обязательны независимо от видимости кнопок.

## Ограничения, которые нельзя скрывать

- Google, Facebook и Instagram имеют обработчики и настройки, но требуют приложений и секретов владельца. Не считать социальный вход проверенным на реальных аккаунтах. Ограничения провайдеров и настройка описаны в `ACCOUNTS-START.md`.
- Почтовое подтверждение, восстановление по письму, платежи и настоящий ИИ-монтаж ещё не подключены.
- Сервер хранит документы монтажа, а исходные видео, музыка и фотографии остаются в браузере. Это не облачная синхронизация медиа между устройствами.
- Нельзя обещать универсальный MP4, полное качество уровня конкурентов или тестирование всех браузеров и длинных проектов.
- Снимки и автономные HTML-демонстрации из чата не заменяют приложение с сервером и реальным входом.

## Запуск из GitHub

Нужен Node.js 22.16 или новее. На новой установке:

```sh
npm install
npm run admin:setup
npm run build
npm start
```

`admin:setup` нужен для первичного создания единственного владельца. Не запускать восстановление с `--reset` без необходимости: оно заменяет данные доступа владельца. В уже настроенной рабочей копии сохраняйте существующую приватную папку.

Адреса после запуска: главная `http://localhost:5173`, монтажёр `/studio`, профиль `/profile`, админка `/krest0208!!!`. Для разработки — `npm run dev`. Полное приложение нельзя запустить одним HTML-файлом без Node-сервера.

Инструкции: [регистрация и запуск](../ACCOUNTS-START.md), [панель владельца](../ADMIN-START.md), [будущая ИИ-интеграция](AI-INTEGRATION.md).

## Секреты и персональная сборка

В публичном репозитории не должно быть готового пароля администратора, API-ключей, OAuth Client Secret, приватной SQLite-базы, `master.key`, подписывающих ключей APK или персонального ZIP-архива из чата.

Учётная запись, созданная в персональной локальной сборке владельца, находится в её `.pokadrovo-private`, а не в GitHub. Не публиковать эту папку и не подменять рабочую базу тестовой. Резервное копирование выполнять отдельно от репозитория после остановки сервера.

В `.gitignore` сохранены прежние исключения и добавлены шаблоны персональных архивов, файлов паролей, дополнительных форматов баз и закрытых ключей. `.gitignore` не удаляет уже отслеживаемые файлы и не заменяет проверку содержимого перед коммитом. При случайной публикации секрета нужна его замена, а не только новый коммит с удалением.

`dist/`, `node_modules/` и приватная база не требуются для хранения исходников в Git. `dist/` создаётся командой сборки. Не переносить в исходники старую самостоятельную HTML-оболочку поверх актуального приложения.
