# Размещение Покадрово

18 октября 2026 на выделенном VDSina `138.16.185.3` установлена версия `951066c`: 57 серверных тестов, TypeScript и сборка прошли; службы приложения и Caddy запущены. Главная, `/studio` и `/projects` отвечают 200, `/admin` — 404, закрытые API — 401. DNS `pokadrovo.ru` ещё не переключён, внешний HTTPS и создание владельца не завершены. Следующие изменения нужно отдельно доставить на сервер; коммит в GitHub сам по себе VPS не обновляет.

## Архитектура

Один домен → HTTPS-прокси Caddy → один Node.js-сервер → закрытый постоянный том SQLite и ключей. Этот же сервер отдаёт собранную главную, редактор, проекты и админ-панель. Клиент обращается только к своему домену; CORS или отдельный адрес API не нужны.

### Выделенный VDSina для pokadrovo.ru

`deploy/install-vdsina.sh` подготовлен для первой установки на отдельный Ubuntu-сервер `138.16.185.3` и обслуживает строго `pokadrovo.ru`. Он запускает прежний Node.js/SQLite-код через systemd, устанавливает Caddy и оставляет порт приложения доступным только на `127.0.0.1`. Данные находятся в `/var/lib/pokadrovo`, вне исходников и каталога сайта.

Скрипт отказывается работать на другом IP, поверх существующей установки или с изменённой конфигурацией Caddy. Он не меняет DNS, другие домены и общие хостинги и не создаёт стандартный пароль владельца. После установки нужно настроить именно `pokadrovo.ru` в REG.RU и один раз создать владельца интерактивной командой, которую выведет скрипт. Первая установка версии `951066c` проверена на реальном VPS с Node.js 22.22.1.

Для случайного начального пароля после доставки актуального `server/setup.mjs` выполните в своём приватном терминале VPS:

```sh
runuser -u pokadrovo -- env POKADROVO_DATA_DIR=/var/lib/pokadrovo node /opt/pokadrovo/app/server/setup.mjs --generate
```

Пароль генерируется на сервере, показывается только один раз в этом терминале и не попадает в GitHub. Сохраните его в менеджере паролей. После входа по HTTPS откройте **«Сменить пароль»** и задайте собственный пароль. Существующего владельца команда не перезаписывает и с `--reset` не работает.

Запуск из каталога проверенных исходников на выделенном VPS: `sudo bash deploy/install-vdsina.sh`. Команда устанавливает программы, проверяет серверные тесты последовательно, собирает приложение и включает службы. HTTPS станет доступен после настройки DNS.

Описанный ниже контейнерный вариант рассчитан на VPS с Docker Engine и Compose. Для выделенного VDSina можно выбрать установку через systemd выше. Наличие только домена не даёт серверу места запуска.

## Файлы

- `Dockerfile`: сборка приложения и отдельный runtime без npm-зависимостей.
- `compose.yaml`: только локальный доступ через `127.0.0.1:5173`.
- `compose.domain.yaml`: отдельная будущая установка на домене; приложение не публикует порт наружу.
- `deploy/Caddyfile`: HTTPS и передача запросов Node.js с сохранением исходного Host.
- `.env.example`: пустое поле будущего домена, без ключей и паролей.

Не объединяйте два compose-файла флагами `-f` одновременно. Выбирайте локальный или доменный вариант.

## Когда будет разрешено размещение

1. Подготовьте сервер и точное полное имя домена. В этой поставке не предполагается ни `.ru`, ни другое окончание имени Pokadrovo.
2. Скопируйте проект на сервер. Сделайте `.env` из `.env.example`; заполните `POKADROVO_DOMAIN` полным именем **без** `https://`, порта и пути. Оставьте `POKADROVO_ACCOUNTS_ENABLED=0`, чтобы посетителям не нужен был аккаунт.
3. Настройте A-запись домена на сервер. Если есть AAAA, она тоже должна вести на этот сервер. Разрешите входящие 80/443 и убедитесь, что они не заняты другим сайтом.
4. Из каталога проекта подготовьте образ и владельца:

```sh
docker compose -f compose.domain.yaml config --quiet
docker compose -f compose.domain.yaml build
docker compose -f compose.domain.yaml run --rm app node server/setup.mjs
```

Команду создания владельца выполняйте только при первой установке. Если переносите существующий экземпляр, сначала восстановите **весь** его закрытый том из собственной резервной копии; не подменяйте базу и master.key независимо. Гостевые браузерные медиа в этом томе не хранятся.

5. Только для фактической публикации включите профиль HTTPS:

```sh
docker compose -f compose.domain.yaml --profile publish up -d
docker compose -f compose.domain.yaml --profile publish ps
```

Именно последняя команда запуска открывает внешние порты. Без профиля `publish` HTTPS-сервис не запускается. Caddy получает сертификат после доступности домена и сервера, а не при подготовке архива.

6. Проверьте главную, прямое открытие `/studio`, создание и повторное открытие проекта, загрузку медиа и экспорт. Введите вручную `https://ВАШ-ДОМЕН/krest0208!!!`, войдите и проверьте сохранение API-настроек. Наличие ключа ещё не включает обработчик ИИ.

Логи: `docker compose -f compose.domain.yaml --profile publish logs --tail=100`.

Остановка без удаления данных: `docker compose -f compose.domain.yaml --profile publish stop`.

## Данные и обновления

Том `private-data` хранит SQLite и master.key, `tls-data` — TLS-данные. Перед обновлением остановите приложение и сделайте резервную копию целого приватного тома. Не выполняйте `down -v` для обычной остановки: это удаление томов.

Исходники, `dist` и Docker image не должны содержать настоящих API-ключей, паролей или приватной базы. Ограничения Host/Origin, CSRF, HttpOnly-cookie и проверки владельца остаются включёнными. В этой версии сервер не доверяет произвольному X-Forwarded-For; за прокси ограничения частоты запросов могут суммироваться для посетителей.

## Проверки и границы готовности

Проверяются сборка TypeScript/Vite, серверная авторизация, гостевой доступ к редактору, изоляция данных и отдельный запуск из готовой поставки. Нативная установка приложения на VPS проверена, но получение сертификата и внешний HTTPS ещё не проверены. Контейнерный вариант отдельно на VPS не запускался.

Основа конфигурации Caddy: https://caddyserver.com/docs/quick-starts/https и https://caddyserver.com/docs/caddyfile/directives/reverse_proxy .
